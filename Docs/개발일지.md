**확인한 것 (2026-09-14 · wrangler dev 실호출)** — `/api/ldong` 16건 · `?regn=30` 5건 · `places?code=30140&type=39` 39건 · `12730`(구례) 142/106 · **`36110`(세종) 204/169 — `lDongRegnCd=36&lDongSignguCd=110`은 0건이라 `36110/36110` 특례로 구현** · `28125`(제물포구) 189/162 · `place/1807489` 광천식당 · `intro?type=39` firstmenu=두부두루치기. 잘못된 파라미터·중복 키·type=38·미정의 경로 → 400/404. 같은 요청 2회째 hit. **검증 뒤 추가한 것** — ① **3층 캐시**(메모리 → KV → Cache API): `*.workers.dev`에서는 Cache API가 동작하지 않아(커스텀 도메인 전용) KV가 실질 캐시가 됩니다 → 배포 후 KV 생성 필수. 429는 메모리에 60초 부정 캐시. ② **레이트리밋 바인딩**(`[[ratelimits]]` IP별 분당 120) — 워커 URL로 공사 한도를 태우는 남용 방지. ③ 공개 `rows` 파라미터 제거(값을 바꿔 캐시 키를 달리하던 구멍).

**남은 것** — 배포는 사용자의 `npx wrangler login` 뒤에(비대화형 환경에서는 CLOUDFLARE_API_TOKEN 필요). 배포 후 `/api/health`에서 `keyConfigured·cache.kv·rateLimit` 셋 다 true인지, 같은 URL 2회 호출로 hit인지, `npm run tail`로 cron 로그가 찍히는지 확인. Flutter 빌드가 나오면 `[assets] directory`를 `../flutter/build/web`으로. 실제 한도 초과(429) 경로는 실호출로 만들 수 없어 단위 실행으로만 검증했습니다.
